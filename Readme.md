## 📌 과제 소개 (Project Introduction)
본 프로젝트는 **언리얼 엔진 5(UE5)의 Dedicated Server(데디케이티드 서버) 아키텍처와 멀티플레이 네트워크 프레임워크를 깊이 있게 이해하기 위해 진행된 과제**입니다. 

단순한 로컬 게임이 아닌, 여러 클라이언트가 접속해 실시간으로 상호작용하는 환경을 구축하기 위해 친숙한 규칙의 '숫자 야구(Bulls and Cows)'를 멀티플레이 환경으로 재해석했습니다. 특히 **서버와 클라이언트 간의 엄격한 권한(Authority) 분리**, **RPC를 활용한 통신**, 그리고 **C++와 UMG(UI)의 동적 연동**을 구현하는 데 중점을 두었습니다.

## 🚀 구현 과정 (Development Log)

본 프로젝트는 복잡도를 낮추고 안정성을 확보하기 위해 **게임 로직(숫자 야구)을 배제한 '순수 채팅 시스템'을 먼저 완벽하게 구축한 뒤, 그 위에 코어 로직을 결합**하는 점진적 아키텍처 설계 방식을 채택했습니다.

### 📍 [Phase 1] 채팅 시스템 선행 구현 및 네트워크 뼈대 구축
* **도메인 로직 분리**: 처음부터 야구 게임을 만들지 않고, 다수의 클라이언트가 서버를 거쳐 실시간으로 텍스트를 주고받는 **채팅 통신망 구축을 최우선 과제로 진행**했습니다.
* **RPC 통신망 완성**: 클라이언트(`PlayerController`)가 텍스트를 입력하면 `Server RPC`로 데디케이티드 서버에 전달하고, 서버는 접속자 명부(`TActorIterator`)를 순회하며 전체 유저에게 `Client RPC`를 쏴주는 '전체 방송(Broadcast)' 뼈대를 완성했습니다.
* **상태 동기화(Replication)**: 채팅창에 표시될 유저의 닉네임과 정보를 관리하기 위해 `PlayerState`를 설계하고, `bReplicates = true`를 통해 서버의 데이터가 모든 클라이언트에게 안전하게 복제되도록 세팅했습니다.

### 📍 [Phase 2] 숫자 야구 코어 로직 결합
* **난수 생성 및 심판 로직 추가**: 튼튼하게 완성된 채팅 시스템 위에서 작동할 `GameMode` 전용 코어 로직(1~9 사이의 중복 없는 3자리 난수 생성기, Strike/Ball 판독기)을 개발했습니다.
* **통신과 로직의 결합**: 유저가 채팅을 치면, 서버가 단순 방송을 하기 전에 입력된 텍스트가 '정답 형식'인지 먼저 판독하고 결과를 덧붙여서(예: `123 -> 1S 1B`) 방송하도록 기존 채팅 시스템과 게임 로직을 유기적으로 결합했습니다.

### 📍 [Phase 3] 치명적인 동기화 및 논리 버그 픽스 (Trouble Shooting)
* **[Bug Fix] 횟수 갱신 지연(역체감) 현상 해결**: 
  * *원인*: 클라이언트가 텍스트를 보낼 때 본인의 과거 횟수(예: 0/3)를 직접 조립해서 전송하여 서버의 갱신 타이밍과 어긋남.
  * *해결*: 문자열 조립 권한을 서버로 이관. 클라이언트는 순수 텍스트("123")만 보내고, **서버가 횟수를 먼저 1 증가시킨 직후의 최신 `PlayerState`를 읽어 문자열을 조립**하도록 데이터 흐름을 교정했습니다.
* **[Bug Fix] 무승부 판정 시 발생하는 무한 루프 폭탄 해결**: 
  * *원인*: 방 인원수만큼 반복문을 도는 도중, 타겟 유저가 아닌 채팅을 친 본인의 상태만 반복 조회하는 섀도잉 발생 및 루프 내부에서 `RestGame()`이 중복 호출됨.
  * *해결*: 참조 대상을 정확히 수정하고, `bIsDraw` 플래그를 활용하여 **반복문이 완전히 끝난 후 바깥에서 단 1회만 게임이 리셋**되도록 리팩토링했습니다.

### 📍 [Phase 4] 서버단 철벽 방어 및 예외 처리 (Validation)
* **3중 검문소(`ValidateGuessInput`) 구축**: 유저의 실수나 악의적 입력을 방어하기 위해 서버에 유효성 검사 로직을 도입했습니다.
* **일반 채팅과 정답 시도의 분리**: 입력값에 숫자가 아닌 문자가 섞인 경우, 기회를 차감하지 않고 일반 채팅으로 전환하도록 분기 처리했습니다.
* **조기 종료(Early Return) 패턴 적용**: "12"(길이 부족), "112"(중복), "045"(범위 오류) 혹은 기회를 모두 소진한 상태에서의 입력 시, 전체 방송을 타지 않고 **해당 유저에게만 1:1 시스템 경고 메시지(`Client RPC`)를 보낸 뒤 로직을 즉시 종료(`return`)**하도록 방어막을 세웠습니다.

### 📍 [Phase 5] UMG와 C++ 동적 연동 (UI Polishing)
* **허공의 디버그 텍스트에서 실제 UI로 전환**: 10초 만에 사라지는 디버그 메시지(`AddOnScreenDebugMessage`)를 제거하고, 실제 게임용 스크롤 채팅 UI(`WBP_ChatInput`)를 C++(`UONBChatInput`)와 바인딩했습니다.
* **동적 텍스트 블록 및 자동 스크롤**: 새로운 채팅이 수신될 때마다 `UTextBlock`을 동적으로 생성하여 Slate 폰트 사이즈(`FSlateFontInfo`)를 조절해 삽입하고, `ScrollBox->ScrollToEnd()`를 호출해 항상 **가장 최신 채팅으로 자동 스크롤**되는 완벽한 인게임 UX를 완성했습니다.

## 🛠️ 트러블 슈팅 (Trouble Shooting)

개발 과정에서 마주친 치명적인 동기화 및 논리 오류들을 다음과 같이 해결했습니다.

### 1. 동기화 타이밍 버그 (Replication Timing Issue) 해결
* **문제 상황**: 클라이언트 화면에 출력되는 본인의 시도 횟수(예: 1/3)가 실제 서버의 횟수보다 한 박자 늦게 표시되는 역체감 버그가 발생했습니다. 클라이언트가 채팅을 칠 때 본인의 `PlayerState`를 읽어 미리 문자열을 조립해 서버로 보낸 것이 원인이었습니다.
* **해결 방안**: 문자열 조립의 권한을 서버로 이관했습니다. 클라이언트는 순수한 입력 텍스트("123")만 서버로 전송하고, **서버가 `GameMode`에서 횟수를 먼저 증가시킨 직후, 최신화된 `PlayerState` 정보를 읽어 최종 문자열을 조립**하도록 데이터 흐름을 수정하여 완벽한 동기화를 달성했습니다.

### 2. 무승부(Draw) 판정 루프 버그 해결
* **문제 상황**: 방에 있는 유저 중 단 한 명이라도 횟수를 모두 소진하면 무승부로 처리되어 게임이 조기 종료되는 버그와, 유저 수만큼 게임 리셋(`RestGame()`)이 중복 호출되는 심각한 서버 자원 낭비가 발생했습니다.
* **해결 방안**: 무승부 검사 반복문(`for`) 안에서 당사자(`InChattingPlayerController`)가 아닌 순회 중인 대상 유저(`ONBPlayerController`)의 횟수를 검사하도록 참조 오류를 바로잡았습니다. 또한, 반복문 안에서 호출되던 `RestGame()`을 반복문이 완전히 종료된 후 루프 바깥에서 **단 1회만 호출**되도록 리팩토링하여 서버 성능 저하를 방지했습니다.
